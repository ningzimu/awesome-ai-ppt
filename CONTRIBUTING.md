# Contributing

Thanks for helping improve Awesome AI PPT.

This is a curated list, not a directory of every presentation product. Prefer fewer high-quality entries over broad coverage.

感谢你帮助改进 Awesome AI PPT。

这是一个精选清单，不是所有演示产品目录。我们更偏向少量高质量条目，而不是尽可能多地收录。

## Inclusion Criteria / 入选标准

Good candidates should meet most of these:

- Directly related to AI-assisted presentation generation, PPTX editing, slide conversion, deck reconstruction, rendering, QA, or evaluation.
- Public GitHub repository, research artifact, or open technical resource.
- GitHub repositories should have at least 10 stars.
- Clear README, documentation, example, demo, or paper.
- Visible license when source code is included.
- Active maintenance in the last 12 months, or stable enough to justify keeping.
- Clear input and output formats, such as prompt to PPTX, PDF to slides, HTML to PPTX, or Markdown to deck.

好的候选项目通常应满足：

- 与 AI 辅助演示生成、PPTX 编辑、幻灯片转换、deck 可编辑重建、渲染、QA 或评估直接相关。
- 是公开 GitHub 仓库、研究产物或开放技术资源。
- GitHub 仓库通常至少需要 10 stars。
- 有清晰的 README、文档、示例、demo 或论文。
- 如果包含源码，应有明确许可证。
- 最近 12 个月内仍在维护，或足够稳定、值得保留。
- 输入与输出格式清晰，例如 prompt to PPTX、PDF to slides、HTML to PPTX 或 Markdown to deck。

Avoid / 避免收录：

- Generic AI writing tools with no presentation workflow.
- Generic image generators with no slide or deck output.
- Pure template marketplaces.
- Empty repositories, dead links, or projects with no README.
- Archived, deprecated, or abandoned projects. Use `ARCHIVE.md` for historical references.
- Marketing descriptions such as "best", "revolutionary", "powerful", "magic", or "game-changing".
- 没有演示工作流的泛 AI 写作工具。
- 没有幻灯片或 deck 输出的泛图片生成工具。
- 纯模板市场。
- 空仓库、死链或没有 README 的项目。
- 已归档、废弃或无人维护的项目。历史参考请放入 `ARCHIVE.md`。
- “best”、“revolutionary”、“powerful”、“magic”、“game-changing” 这类营销描述。

## Entry Format / 条目格式

Use one short factual sentence:

```md
- [owner/repo](https://github.com/owner/repo) - Short factual description.
```

Rules:

- Link to the canonical GitHub repository when possible.
- Use the project name or `owner/repo` as the link text.
- Start the description with a capital letter.
- End the description with a period.
- Keep descriptions objective and useful.
- Put the entry in the category where readers would most likely look first.
- Keep entries alphabetized within each category.

规则：

- 尽量链接到规范的 GitHub 仓库。
- 链接文字使用项目名或 `owner/repo`。
- 英文描述首字母大写。
- 英文描述以句号结尾。
- 描述保持客观、实用，不写广告语。
- 放到读者最可能查找的分类中。
- 同一分类内按字母顺序排列。

## Pull Requests / PR 规则

- One pull request should add, remove, or update one project.
- Explain why the project belongs on the list.
- Mention the expected input and output formats when relevant.
- Do not add a new category in the same pull request as a project entry.
- Do not move unrelated entries.
- 每个 PR 只新增、删除或修改一个项目。
- 说明这个项目为什么应该被收录。
- 如果相关，请说明输入和输出格式。
- 不要在新增项目的同一个 PR 里新增分类。
- 不要移动无关条目。

## Categories / 分类

Current categories:

- End-to-End AI Presentation Tools
- Agent Skills and Workflows
- PowerPoint and PPTX Libraries
- Editable Reconstruction
- Markdown, HTML, and Document to Slides
- Research and Benchmarks
- Directories and Related Lists

If a project fits multiple categories, choose the one that best matches its primary use.

如果项目适合多个分类，请选择最符合其主要用途的分类。
